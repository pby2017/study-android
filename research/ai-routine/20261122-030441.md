## Evidence

- koog-compose is an independent project layered on JetBrains Koog, not an official JetBrains Koog subproject.
- README describes a `koogCompose { }` DSL, typed application state exposed as StateFlow, phased agent flow, and separate modules for UI/device/Room/testing.
- Android provider: Gemma 4 via LiteRT-LM. iOS provider: Apple Foundation Models (iOS 26+). These are platform-specific, not a single cross-platform backend.
- README explicitly warns that APIs may change despite the tagged v2.1.0 release and says to pin versions/read release notes. The same README says an unavailable local model may invoke the configured cloud fallback; the provider may receive conversation messages, tool results, tool names/arguments, and application context.
- GitHub showed 15 stars / 0 forks for koog-compose; JetBrains/koog 4.7k stars; google-ai-edge/mediapipe 37.8k stars at review. These volatile signals make koog-compose a small, early project, not a popular dependency. Recent visible CI activity is evidence of active changes, not adoption or production maturity.
- License in README is Apache-2.0. The old card's MIT label was wrong.

## Decision

- Keep only as an AI+Android reference example because its Android-specific local model + device-tool + Compose state integration is directly educational.
- Do not recommend it as a mature or popular production dependency. State third-party/early-stage caveat and require version pinning, device testing, and a deliberate cloud-fallback policy.
- Confidence: high for README-described API/platform claims; medium for real-world reliability (no independent usage evidence).
