## Evidence and decision
- The repo README describes a model-centric Android worker that gets models/training plans from PyGrid, trains against local device data, and reports updates. Its README's install snippet still says 0.1.3, while the GitHub releases page lists a later 0.5.0 release candidate; treat its docs as stale rather than current installation guidance.
- README lists charge, sleep/wake, Wi-Fi/metered-network safeguards. Secure aggregation and MPC are explicitly marked “in progress” in the README, so the previous card incorrectly presented them as supported.
- OpenMined's announcement explains the old PySyft/PyGrid model-centric architecture and notes secure aggregation/WebRTC were not supported at initial release.
- PMLR research demonstrates that even aggregated model updates may leak participant information under repeated observations; NIST describes secure aggregation as protecting individual updates from the aggregator. Therefore, local raw-data retention alone is not a privacy guarantee.
- GitHub repo page displayed 89 stars and 24 forks; the release page's latest displayed release is 0.5.0 RC. Popularity is modest; this is not a current hot/adoption candidate.
- Retain only as a clearly labeled legacy architecture/privacy lesson. Do not recommend adoption or claim current PySyft compatibility. Confidence: high for historical design and stated maturity caveats; low for present-day installability (not tested).
