# Android AppFunctions 1.0 card refinement

- Date: 2026-11-22 (KST)
- Candidate: existing `Android AppFunctions 1.0` AI+Android card
- Decision: retain and refine; this is Android's on-device app-capability interface for agents, not a pure Android implementation topic.
- Attention / freshness: AndroidX release notes show AppFunctions 1.0.0, compiler, and testing artifacts became stable on 2026-11-18. The official Android AI overview and an Android Developers engineering post cover current implementation and testing workflows. No volatile GitHub star number was needed or added.
- Fact checks:
  - AndroidX release notes identify 1.0.0 as Stable, released 2026-11-18.
  - Current overview says Android 16+; an app can call functions in its own package, while cross-app discovery/calls require privileged `EXECUTE_APP_FUNCTIONS`, held by authorized system assistants.
  - Gemini access is not implied by library stability: Google requires the Connected Apps Platform developer preview and connected-app publication/testing workflow.
  - `@AppFunctionDeclaration` metadata/KDoc helps agents select functions; annotated functions run on the main thread by default, so blocking work must be moved off it.
  - Android's implementation guide documents ADB registration/execution checks; current Android Developers blog scopes those ADB commands to Android 17+ devices/emulators. Device registration does not prove an agent will choose the right function; test agent selection separately.
- Corrections: removed the stale claim that current Android docs label the feature an experimental preview; qualified cross-app permission instead of implying every caller needs it; distinguished library stability, Android platform support, and Gemini preview access.
- Duplicate check: searched `_data/cards.yml` for AppFunctions, Android MCP, and app-function/agent-tool concepts. There is a brief AppFunctions mention in the Android security-roadmap card, but no duplicate implementation/agent-integration lesson.
