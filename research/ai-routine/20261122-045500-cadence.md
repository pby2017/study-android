## Evidence and decision
- GitHub showed 4 stars, 0 forks, and 55 commits at review. The README links a v0.6.0 APK for Android 10/API 30+ and a closed Play test. Treat this as a small prototype/case study, not a popular or production-proven recommendation. The visible root file list had no LICENSE; do not label it open source or imply code reuse is licensed.
- README describes two configurable HTTP stages: biometric context to an LLM, then song parameters to a text-to-music endpoint. `app/build.gradle.kts` defaults the LLM URL to OpenRouter and the music URL to Cadence API; app settings/local properties can change them. The README also lists local Ollama/vLLM and self-hosted generation options. “Local LLM” alone does not make the second endpoint local, and server-local inference is not automatically on-device inference.
- `PromptBuilder.kt` includes activity, heart rate, SpO2, GPS coordinates formatted to four decimal places, steps, sleep, time, and related context. `MusicRepository.kt` sends that context as the LLM user message and logs it with `Log.d` through `logChunked`. Release minification is configured, but source/config alone does not prove these log calls are removed from a release artifact; the card asks developers to verify release logcat behavior rather than claim a confirmed production leak.
- Privacy policy says raw readings remain on-device and only anonymised summaries are transmitted; the code shows a derived context (including rounded location and health/activity values) is sent to the configured LLM endpoint. A lack of direct identifiers does not establish that a contextual summary is non-sensitive. This is presented as a data-flow review lesson, not a legal determination.
- One documentation discrepancy: README gives MiniMax Music as a setup example while the checked Gradle default points to the Cadence music API. Card follows the executable Android build default and says endpoints are configurable.
- Retained because the AI+Android example teaches separate network boundaries, contextual health-data minimization, and sensitive log review. Removed stale “iOS·Android”, “open source”, and “fully private” promotional claims.

Confidence: high for README/source/build-configuration behavior; low for actual release-log output, backend retention, and deployed privacy behavior. No Android build, device run, network capture, or release logcat inspection was performed.
