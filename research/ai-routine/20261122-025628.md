## Card decision and edits

- Published one concise comparison card: `Android 온디바이스 RAG 벡터 검색 — ObjectBox HNSW vs SQLite-Vector`.
- Kept practical selection criteria: integrated Kotlin object + HNSW ANN vs existing SQLite + extension/BLOB search.
- Clarified that a vector store finds relevant chunks; it does not itself generate embeddings or LLM answers.
- Removed claims not supported by the checked evidence or too easy to overgeneralize: ObjectBox `<8MB`, KB RAM, old-device `0.25ms/4k QPS`, LangChain integration; SQLite fixed `30MB` memory and broad ecosystem claims.
- Added interview prompt emphasizing target-device latency, memory, recall, embedding dimensions, and distance-metric validation.
- Confidence: high for core features; performance comparison deliberately omitted because no apples-to-apples Android benchmark was verified.
