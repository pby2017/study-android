# Card refinement: Novu MCP and ACI

- Reviewed: 2026-11-22 02:28 KST
- Card: `Novu MCP·ACI — AI 에이전트를 메시징 채널과 연결하는 대화 인프라`
- Decision: Refined and retained as an AI + Android backend integration lesson.

## Sources checked

- [Novu MCP Server docs](https://docs.novu.co/platform/build-with-ai/mcp) — AI clients can access subscriber, workflow, delivery, agent, and conversation operations; requires Novu Cloud account and authenticated MCP client.
- [Novu SDK overview](https://docs.novu.co/platform/sdks) — official React Native SDK; no native Android client SDK; server SDKs and REST API can trigger workflows; non-JavaScript clients need a custom Inbox via REST API.
- [Novu API key docs](https://docs.novu.co/platform/developer/api-keys) — application identifier is public, but the secret key grants full environment access and must not be exposed in mobile code.
- [Novu FCM integration guide](https://docs.novu.co/platform/integrations/push/fcm) — configure FCM, register device tokens on a subscriber, and trigger push delivery from server SDKs or REST API.
- [Novu GitHub README](https://github.com/novuhq/novu) — current ACI description: normalizes inbound channel messages, routes them to an existing agent, and returns its response; Novu provides communication infrastructure, not the agent's reasoning.

## Corrections and rationale

- Replaced the old card's generic notification-platform pitch and unsupported fixed star count with Novu's current AI-relevant MCP and ACI capabilities.
- Clarified that MCP lets an AI client operate a Novu account; it does not make Novu an LLM or execute the agent's inference.
- Added the Android deployment boundary: workflow triggering and FCM delivery are backend-side; native Android has no official Novu client SDK or built-in Inbox UI, so an in-app inbox requires a custom REST-based UI.
- Added a security interview question that distinguishes public application identifiers from secret keys, which must remain server-side.
- GitHub showed 40.4k stars during this review. This volatile signal supports current attention but is omitted from the card and is not treated as evidence of quality.
- Skipped the next card, GrowthBook, because its current card describes generic feature flags/A-B testing and has no central AI workflow. Continued to the next AI-specific candidate, Firebase Remote Config + A/B Testing.
