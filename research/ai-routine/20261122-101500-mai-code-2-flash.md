# MAI Code 2 and MAI Code 2 Flash — 2026-11-22

## Decision

The two existing MAI-Code-1-Flash cards duplicated an obsolete model lifecycle. Consolidate their durable lesson—route lightweight work to a fast/cost-efficient model and complex work to a stronger model—into one current card for MAI Code 2 and Flash.

## Verified facts

- GitHub deprecated MAI-Code-1-Flash across Copilot on September 10, 2026, with MAI-Code-1.1-Flash as the suggested replacement.
- GitHub launched MAI Code 2 and MAI Code 2 Flash in Copilot on November 17. Its current guidance positions Code 2 for complex tasks (deep debugging, multi-file implementation, refactoring, repository-wide reasoning) and Flash for explanations, targeted edits, routine fixes, and rapid iteration.
- GitHub states that availability differs by Copilot plan and client surface. Business and Enterprise administrators manage model policy. The models are billed under usage-based billing; avoid treating the launch descriptions as guaranteed performance or price for every account.
- Microsoft's model card lists text/image inputs and a 1.05M context length for the MAI Code 2 family. Not included in the concise card because the practical distinction by task is more useful and support/model settings may evolve.
- GitHub had scheduled MAI-Code-1.1-Flash deprecation for December 18, 2026. This substantiates the need to avoid long-lived references to Flash v1. This scheduled lifecycle detail is recorded here but omitted from the evergreen card.

## Attention and usefulness signals

- Timely: two new models launched in GitHub's November 17 Copilot release cycle.
- Official adoption: supported in GitHub Copilot's client surfaces, subject to plan, rollout, and policy.
- Practical developer utility: gives a task-based selection heuristic; no unsupported exact stars or benchmark claims are used.

## Card changes

Replaced duplicate, stale v1 cards with one card. Focus: Code 2 for larger/harder repository changes, Flash for simple iterative work, plus usage-based billing and availability checks. Confidence: high for the lifecycle/availability statements; medium for relative task fit because this is GitHub's model guidance, not a guarantee for each individual task.
