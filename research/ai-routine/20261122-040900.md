# MNN-AECS 카드 재검토 — 2026-11-22 04:09 KST

## 후보와 적합성

- 대상: 기존 `MNN-AECS` 카드. 모바일 LLM 추론 최적화와 Android CPU 실행이 핵심이므로 AI+Android 범위에 해당한다.
- 학습 가치: decode 단계의 코어 affinity, 기기별 튜닝, CPU frequency governor 동작이 전력·토큰 속도에 미치는 영향을 설명한다.
- 구별: `PowerLens`는 시스템 설정을 바꾸는 에이전트/권한 경계 연구이고, MNN-AECS는 모델 decode의 런타임 스케줄링 연구다. 에너지 주제는 연관되지만 문제 계층과 권한 모델이 달라 합치지 않았다.

## 확인한 근거

- 논문 원문: https://arxiv.org/html/2506.19884
  - arXiv v1, 2025-06-24 게시. 논문은 Android에서 `sched_setaffinity`로 CPU 코어를 묶고, iOS에서는 thread 수를 조정한다고 설명한다.
  - 평가 범위: Android 5대 + iOS 2대, 5개 LLM, 4개 데이터셋. 원본 MNN 대비 에너지 평균 23% 절감을 보고한다.
  - 결과의 조건 의존성: Meizu 21은 OS가 idle cluster 주파수를 내리지 않아 약 10% 절감에 그쳤다. Huawei 기기 두 대는 데이터셋 평가에서 1%/7% decode slowdown을 보였고 나머지 기기는 1~20% 빨라졌다고 저자들이 보고한다. 따라서 무조건적인 “무손실 23% 절감” 표현은 부정확하다.
  - Android 에너지 측정에는 `BatteryManager` 값을 별도 thread에서 읽어 JNI로 전달하는 평가 구성이 쓰였다. 논문은 상용 앱 적용에 root/OS 수정이 필요 없다고 주장하지만, modified MNN을 전제로 한다.
- upstream 저장소: https://github.com/alibaba/MNN
  - 검토 시점 GitHub UI: 16.6k stars, 2.5k forks, 3,304 commits; MNN 프로젝트의 폭넓은 관심/활동 신호이지 AECS 자체의 채택 증거는 아니다.
  - 현재 `master`의 recursive tree에서 `AECS`/`adaptive energy` 이름을 가진 파일은 0개. GitHub repository search의 정확한 “MNN-AECS” 검색 결과도 0개. 공개된 별도 재현 저장소는 이번 검색에서 찾지 못했다.
  - 그러므로 일반 MNN 공개 구현에 논문 수정이 포함됐거나 즉시 적용 가능한 기능이라는 식으로 쓰지 않는다.

## 결정 및 변경

- 유지하되 연구/시스템 설계 사례로 재구성. headline의 “23% 절감”을 추천·보장처럼 제시하지 않는다.
- 카드에는 평균값과 함께 기기별 편차(약 10~42%), governor 의존성, Huawei 실험의 최대 7% slowdown, upstream에서 AECS 코드가 확인되지 않았다는 재현성 경계를 넣었다.
- 교차 엔진의 39~78% 절감 및 12~363% 속도 향상 수치는 비교 조건과 모델 지원 차이를 카드 공간에서 충분히 설명하기 어려워 제거했다.
- 인터뷰 답은 같은 기기·모델에서 에너지, decode 속도, 발열을 함께 재고, governor 동작과 실행 가능한 구현을 확인하도록 구성했다.
- 정확한 star 수는 volatile하므로 카드에서 생략; 연구 관심의 보조 신호로만 기록했다.

## 미수행/한계

- Android 실기기에서 MNN-AECS를 직접 빌드·재현하지 않았다. 이번 확인은 논문과 공개 GitHub 상태에 근거한다.
- 논문 자체의 실험 변동성/독립 재현은 확인되지 않았다. 23%는 저자 보고 평균으로만 표시한다.

Confidence: medium-high — 논문 핵심 결과와 명시된 device caveat는 원문으로 확인. 현 공개 구현 여부는 현재 upstream tree 및 정확한 repository 검색 범위에 한정.
