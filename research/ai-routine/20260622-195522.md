## 후보 검토

### 선택: LiteRT-LM

- 분류: AI+Android
- 핵심 주장: LiteRT-LM은 LiteRT 기반 LLM 실행 오케스트레이션 계층이며 Android 등 edge 플랫폼에서 CPU/GPU/NPU 백엔드, 세션 관리, 멀티모달, function calling, constrained decoding을 포함한 온디바이스 LLM 배포 기능을 제공한다.
- 소스:
  - https://developers.googleblog.com/blazing-fast-on-device-genai-with-litert-lm/
  - https://developers.google.com/edge/litert-lm/overview
  - https://github.com/google-ai-edge/LiteRT-LM
- 최신성/신호:
  - Google Developers Blog 게시글은 최근 게시된 공식 자료.
  - Google AI Edge 공식 문서와 GitHub 저장소가 동일하게 "production-ready orchestration layer to run LLMs with LiteRT"라고 설명.
  - 공식 블로그가 Android, iOS, Web 성능과 Google 제품/AI Edge Gallery 사용 맥락을 제시.
- 실행 중 확인한 정확 수치:
  - Gemma 4 E2B Android GPU backend decode: 52 tokens/sec.
  - Multi-Token Prediction 적용 시 최대 2.2x decoding speedup.
  - 위 수치는 공식 Google Developers Blog 근거이며 카드에 사용.
- 중복 점검:
  - 기존 카드에는 ML Kit GenAI 지원표, ML Kit GenAI 쿼터, Gemini Nano 버전 체크, Tensor SDK Beta + LiteRT, LiteRT + Arm SME2, ExecuTorch 등이 있었으나 `LiteRT-LM` 제목/각도는 없음.
- 선정 이유:
  - 순수 Android 구현 주제가 아니라 온디바이스 LLM 런타임/배포 계층이라는 AI+Android 교육 주제.
  - Android 개발자가 온디바이스 AI 기능을 설계할 때 모델보다 런타임 제약 관리가 중요하다는 실무 가치가 분명함.
- 신뢰도: 높음
