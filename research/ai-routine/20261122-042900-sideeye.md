## Evidence and attention
- GitHub page showed 1 star, 0 forks, and 18 commits (checked 2026-11-22); no release was listed.
- README says Copyright 2026 Baseweight, all rights reserved. Do not imply that the source is open-source or recommend reusing it.
- README says Android 9/API 28+, Qualcomm NPU required for Smart Scan, and model download is about 2.4 GB. `ModelDownloader.kt` directly accesses the project S3 model hub with a Hugging Face fallback.
- `ImageAnalyzer.kt` sends a local image path plus a classification prompt to Nexa `VlmWrapper`, parses `Category: N`, and sets `primaryConfidence` to 1.0 for a flagged label or 0.0 otherwise. This is binary label encoding, not a model probability or calibrated confidence score.
- `VaultRepository.kt` uses AndroidX `EncryptedFile` with AES-256-GCM-HKDF; the README's AES claim has a checked implementation path. Vault encryption does not validate the moderation model or imply full-app protection.

## Decision
- Keep only as an attributed code-review case study, not as a product recommendation. Replace the feature/marketing overview with the transferable lesson that generated labels and calibrated confidence are different, then require class-wise evaluation and a human-review path for uncertain/high-impact moderation.
- Preserve the runtime caveat: this specific Smart Scan implementation is Qualcomm-NPU-bound and has a large initial model download; do not generalize it to all Android phones.
- Confidence: high for checked source-code behavior; no device build/run or VLM accuracy evaluation was performed. Low confidence in general product maturity because adoption evidence is very small.
- Next: determine whether `ORB-SLAM2s(Android)` is genuinely an AI topic or an out-of-scope classical CV/Android implementation.
