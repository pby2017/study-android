## 후보 판단

- 대상: `vision_ai` Flutter 카메라 AI 플러그인 카드.
- 공식 저장소는 실제 AI+Android/iOS 개발 범위에 해당하고, native CameraX/MediaPipe/ML Kit/TFLite 경로 및 모델 패키지 분리를 설명한다. 물리기기 기록도 Android에서 hand/face inference가 동작했음을 보여준다.
- 그러나 카드의 핵심 USP인 25–30 FPS는 README/pub.dev에서 재현 가능한 벤치마크 조건(기기별 표, 입력 크기, delegate, 동시 기능, steady-state)이 제공되지 않는다. 저장소의 `test_evidence/physical_findings.md`는 camera lifecycle, front-camera overlay, Android 16 16 KB compatibility, iOS/animal coverage의 테스트 경계도 별도로 기록한다.
- GitHub API / package pages 확인: 4 stars, 1 fork, 44 commits; 마지막 push 2026-08-27. pub.dev latest 확인 버전은 0.4.0이며 2 likes. 널리 주목받거나 많이 활용된다는 신호가 약하다.
- 기존 `MediaPipe Tasks` 카드는 Android live-camera ML의 핵심 API, IMAGE/VIDEO/LIVE_STREAM, device profiling 원칙을 이미 설명한다. `vision_ai`의 넓은 기능 목록은 그 인접 주제와 겹치며 독립적인 추가 학습 가치가 낮다.

## 결정

- 공개 `_data/cards.yml`에서 `vision_ai` 카드를 삭제해 낮은 채택 신호와 검증 조건이 부족한 FPS 홍보 문구를 제거했다.
- 삭제는 프로젝트의 MediaPipe 학습 카드를 제거하지 않는다. 기존 Google 공식 MediaPipe Tasks 카드가 더 일반적이고 재현 가능한 학습 기반을 제공한다.
- `auto-post-log.md`의 기존 발행 기록은 감사 이력으로 보존한다.
- 고려한 보수 대안: `vision_ai`를 Android integration 사례로 재작성. 다만 독립 토픽으로서 관심·고유성 근거가 약하고 기존 MediaPipe 카드와 중복되어 제외가 더 적합하다고 판단했다.
