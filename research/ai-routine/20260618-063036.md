### Prompt caching

- Card title: `Prompt caching — 에이전트 비용을 줄이는 첫 번째 레버`
- Practical developer value: High. Long agent sessions repeatedly send stable system prompts, tool definitions, repository guidance, and prior context; caching strategy directly affects latency, usage limits, and API cost.
- Current relevance: Active official API feature across major model providers, and especially relevant to long-running coding agents with large tool and instruction prefixes.
- Popularity/attention signal: Present in official Anthropic and OpenAI API documentation; recent research evaluates caching for multi-turn agent workloads.
- Source URLs checked:
  - https://platform.claude.com/docs/en/build-with-claude/prompt-caching
  - https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching
  - https://developers.openai.com/api/docs/guides/prompt-caching
  - https://arxiv.org/abs/2601.06007
- Fact-check signals:
  - Anthropic docs: cache prefixes are structured in the order `tools`, `system`, then `messages`; static content should be placed at the beginning and marked with `cache_control`.
  - Anthropic tool-use caching docs: changes at earlier prefix levels invalidate that level and everything after it, so changing tools invalidates more cache than changing later messages.
  - OpenAI docs: prompt caching works automatically for repeated prefixes on supported requests and is useful for lowering cost and latency.
  - 2026 research paper: prompt caching for long-horizon agentic tasks reports large cost and time-to-first-token gains, with better outcomes when dynamic content is placed later instead of naively caching everything.
- Selected reason: Strong practical value, official primary sources from two providers, and a queued candidate not already present in `_data/cards.yml`.
- Confidence: High.
