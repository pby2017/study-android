## Verified current state

Google announced the CLI on 2026-06-05 as a bridge from a local terminal to remote Colab runtimes, usable by terminal-based AI agents. The upstream repository showed 2.7k stars and 105 commits when checked (a point-in-time interest signal, not a stable popularity guarantee). PyPI showed v0.8.0 as the latest published package, released 2026-11-10, requiring Python >=3.12.

The current workflow offers reusable sessions (`colab new` + `colab exec`) and ephemeral one-shot jobs (`colab run SCRIPT`). `colab run --gpu T4 script.py` allocates a fresh VM, runs the local script, and shuts the VM down by default; `--keep` leaves it running. Explicit session workflows must be stopped when done. The CLI also includes an agent-facing skill document, so an agent can discover command requirements instead of inventing flags.

Accelerator allocation is not guaranteed: the project's operator guide says availability is account/plan gated and a 400 allocation failure indicates missing quota/entitlement; many accounts may only receive CPU. Active/idle runtimes consume Colab compute units; `colab usage` displays balance/rate and `colab stop` releases a named session. The current upstream README says the CLI supports macOS and Linux and does not support Windows. PyPI metadata labels the distribution OS-independent, so the card follows the more specific upstream platform guidance and the mismatch is recorded here.

## Card revision

Replaced launch-era accelerator claims and older command examples with the current `colab run` ephemeral-job lifecycle. Made GPU availability and compute-unit use explicit, distinguished default cleanup from `--keep` and reusable sessions, and added the current upstream OS support limit. The card does not imply a particular accelerator is guaranteed or free.

## Limitations

No authenticated VM was allocated or billed during this content review. Quota, accelerator availability, account plans, and compute-unit rates vary by account and can change; users should inspect current `colab usage` and plan details before launching work.
