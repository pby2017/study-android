## Verified facts
- SDK README lists Kotlin for Android API 24+ and demonstrates `LlamaCPP.register()`, SDK initialization, model download/load, then text generation. ONNX speech and QHexRT acceleration are separate backends/dependencies.
- README says capability discovery is required: enum presence alone does not mean an engine is installed. QHexRT NPU is limited to Snapdragon Hexagon v75/v79/v81 and Android arm64.
- The README says first-use model download occurs; cloud providers/optional hybrid STT exist. Therefore the old “entire voice stack is completely offline” and unconditional privacy wording was too broad. Offline behavior needs models cached and remote routes disabled.
- The Android app README separately lists the NPU backend as unavailable on x86_64 emulators and documents a validated architecture set. It says cloud providers are opt-in/off by default in that app, not necessarily every SDK consumer.
- Version caveat: SDK README Kotlin snippet is at 0.20.27, while the linked Android app README lists SDK AARs at 0.20.24 and QHexRT at 0.20.19; GitHub currently labels v0.20.43 as a desktop-kit release and documents scoped releases. Avoid hardcoding dependency versions; consumers should pin compatible artifacts from current docs.
- GitHub displayed 10.4k stars and 422 forks at review. Strong interest signal, but not proof of production maturity or popularity among Android apps.

## Decision and changes
- Keep the AI+Android topic, but narrow it to the Kotlin local-engine/model lifecycle and device capability constraints.
- Remove unsupported guarantees around full offline speech, LoRA hot-swap and “zero cloud cost” from the card; distinguish optional backends and cloud routes.
- Add an interview prompt that asks how to substantiate offline behavior and hardware acceleration.
- Confidence: high for repository README behavior and listed device boundaries; medium for exact package compatibility because repo and app docs show different version pins.
