# A2UI + MCP Apps refinement — 2026-11-22

## Decision

Refine the existing card rather than add a duplicate. Its original tradeoff was useful but imprecise for Android implementation: native A2UI rendering is not an automatic feature of generic MCP clients. The updated card distinguishes client/rendering prerequisites and gives a practical Compose-focused decision path.

## Verified evidence

- Google Developers Blog (2026-06-17): A2UI sends structured JSON for a host to render with native components; MCP Apps provide HTML/CSS/JS UI in an iframe. The article describes A2UI-over-MCP as a distinct architecture, and notes component-catalog limits versus complex client-side logic. It presents mixed patterns, not a universal best choice.
  - https://developers.googleblog.com/en/a2ui-and-mcp-apps/
- A2UI GitHub repository, checked 2026-11-22: project README describes a data-not-code UI protocol and native renderers, including Jetpack Compose; repository page showed 17.7k stars and 1.4k forks at review time. These counts are a volatile attention snapshot, not evidence of production suitability.
  - https://github.com/a2ui-project/a2ui
- A2UI project docs: Jetpack Compose appears in the renderer list. The project describes registered components and agent-composed surfaces; do not equate a supported renderer with automatic integration into every Android app.
  - https://a2ui.org/
- MCP Apps extension docs: tools declare `ui://` HTML resources; a supporting host displays them in a sandboxed iframe and mediates bidirectional interaction. Host support varies; MCP Apps is an extension, not a guarantee for every MCP client.
  - https://apps.extensions.modelcontextprotocol.io/api/

## Card changes

- Added level and interview Q&A to match the repository's common card format.
- Replaced the generic “A2UI vs iframe” choice with concrete Android/Compose host capability requirements.
- Kept security guidance bounded to component catalogs, iframe sandbox/CSP, and validating host-mediated messages/tool actions; avoid implying that an iframe alone makes an app secure.

## Confidence

High for the protocol and documented renderer/host behavior. Medium for future ecosystem uptake; no forecast or popularity trend is claimed.
