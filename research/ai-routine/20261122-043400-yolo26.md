## Fact check
- YOLO26 official docs describe seven task families: detection, instance segmentation, semantic segmentation, depth estimation, classification, pose estimation, and oriented bounding boxes (OBB). The previous card listed only five.
- NMS-free inference is optional: the one-to-one end-to-end path can be selected (`nms=False` for export); the default one-to-many path still uses NMS. Removed the claim that NMS is always eliminated.
- The “up to 43% faster CPU” result compares YOLO26n against YOLO11n with ONNX Runtime on an Intel Xeon CPU. The ONNX docs say the reported inference-stage latency excludes preprocessing and postprocessing. It is not a mobile benchmark.
- Android export: `format="litert"` produces a `.tflite` model; legacy `format="tflite"` works with deprecation warning. Official Flutter plugin supports Android LiteRT camera and single-image inference.
- Accelerator caveat: current integration docs say MediaTek released plugin support is CPU/GPU; NPU timing uses an unreleased prototype. Do not generalize NPU performance.
- GitHub attention snapshot: ultralytics/ultralytics 63.6k stars, yolo-flutter-app 516 stars (checked 2026-11-22). Popularity is a relevance signal only, not a mobile accuracy guarantee.

## Decision
Retain and reframe as an Android deployment/benchmark lesson: choose LiteRT export, understand the optional NMS-free path, and test end-to-end latency/accuracy on target hardware. Avoid translating Xeon ONNX results into phone speed claims.

Confidence: high for documented behavior and benchmark setup; no Android device measurements were performed for this card.
