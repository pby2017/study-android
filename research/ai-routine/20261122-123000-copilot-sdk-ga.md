# Microsoft Copilot SDK GA and transition — 2026-11-22

## Decision

Refine the existing SDK card. The prior v2/runtime-isolation framing overemphasized one release's implementation detail and omitted product-surface boundaries. Recenter it on SDK as an embeddable programming interface, CLI protocol limits, current rename, and Android-support non-inference.

## Facts checked

- GitHub announced the Copilot SDK as generally available on 2026-06-02, with a stable API for embedding the agent runtime into apps, services, and developer tools. Listed capabilities include planning, tool invocation, file edits, streaming, multi-turn sessions, custom tools/MCP, and tracing.
- GA announcement lists six language ecosystems: Node.js/TypeScript, Python, Go, .NET, Rust, and Java. Do not imply Java first appeared at GA: April preview materials already list it.
- GitHub announced the transition to Microsoft Copilot SDK on 2026-10-28. Migration/rebranding is phased; existing package names and docs may remain, with no immediate change required for existing users.
- Official compatibility docs say SDK communicates with CLI over JSON-RPC; only features exposed through that protocol are available. Some interactive terminal-specific CLI features are not SDK APIs.
- Official quickstart requires Copilot CLI and authentication (bundled for some SDKs; required separately for Go, Java, Rust unless app-level bundling applies). It lists Java 17+, not Android deployment or on-device inference. No Android claim is justified by language support alone.
- GitHub repository page showed 10.7k stars and 1.5k forks when checked on 2026-11-22. Snapshot indicates attention only; it is not a trend, quality, or Android-readiness signal.

## Result

Kept as an AI developer-tool card (not an Android SDK recommendation). Replaced the v2 runtime isolation focus with GA scope, protocol boundary, phased naming, and an interview distinction between Java support and Android runtime support. Confidence: high for product claims; no Android compatibility inferred.
