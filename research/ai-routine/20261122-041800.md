## 교차 확인한 공식 출처

- Agent Mode 문서: https://developer.android.com/studio/gemini/agent-mode
  - high-level prompt를 plan으로 만들고 여러 파일을 변경하며, 빌드 오류 수정 등 multi-step loop를 수행한다.
  - 현재 도구는 연결 기기 배포, 화면 inspection, screenshot, Logcat 조회, `adb shell input` 상호작용을 지원한다.
  - 기본 Gemini 경로에서는 prompt가 Gemini API로 전송되고, 허가된 tool 실행 결과도 Gemini API로 돌아가 다음 응답 생성에 쓰인다. 도구에 따라 사용자의 permission grant가 필요하다.
- Android Studio Otter 3 Feature Drop (2026-01-15): https://android-developers.googleblog.com/2026/01/llm-flexibility-agent-mode-improvements.html
  - 원격 모델 공급자와 LM Studio/Ollama 같은 로컬 모델 선택(BYOM), 변경을 확인하는 drawer, remote MCP, Journeys와의 연결을 설명한다.
  - `Don't ask to edit files` 설정이 꺼져 있으면 변경마다 권한을 요청한다. 여러 편집을 묶어 수락하는 구성도 가능하므로 “항상 각 파일을 수동 승인”이라고 단정하지 않는다.
- Build and run using the AI agent: https://developer.android.com/studio/run
  - 현재 문서는 physical/emulator deploy, screenshots, Logcat, `adb shell` 상호작용을 별도 workflow로 재확인한다.

## 변경 결정

- 기존 핵심(계획 → 다중 파일 수정 → 빌드·기기 검증)을 유지하고, 화면·스크린샷·Logcat·`adb shell input`을 공식 문서 wording에 맞춰 구체화했다.
- 권한 설정이 변경 수락 동작을 바꾼다는 점과 `adb` 조작의 실제 기기 부작용을 드러냈다.
- 기본 Gemini API prompt/tool-result 경로, BYOM 선택, 외부 MCP endpoint를 별도 data boundary로 추가했다. 원격 도구 사용을 “IDE 안에서만 처리”하는 것처럼 보이지 않게 한다.
- 성공 확인은 에이전트의 종료 문장이 아니라 diff, 빌드/테스트 결과, 실제 화면으로 하도록 interview answer를 조정했다.
