## Facts verified

- The MCP server connects compatible AI clients to live AppFollow reviews, ratings, rankings, and ASO data.
- AppFollow's toolkit provides repeatable feedback and ASO workflows; vendor docs mention `/feedback-analysis`, `/aso-analysis`, competitor analysis, and reports.
- MCP permission follows AppFollow role/workspace access: Owners/Admins have read/write, other roles are read-only. Workspace API credits are consumed.
- Vendor data-processing docs say AI replies/summaries use OpenAI API and review title/content plus manually tagged data; the card avoids implying private backend data is sent or that review processing is local.
- Replies can use brand styles and knowledge-base content; draft/review modes are available, while automation depends on account configuration.
- Official GitHub page displayed 4 stars, 0 forks, and one commit at review. This is low and volatile; not treated as popularity proof.

## Removed or qualified

- Removed customer names/claims (`Discord`, `Flo`, `Opera`) because they were unnecessary to the educational point and not independently verified here.
- Removed the old +0.7 statement as an AppFollow effectiveness metric. Google Play's own page describes an average increase to the responded negative review's rating; that is not evidence of an AppFollow-specific effect or a guaranteed app-wide rating increase.
- Added the practical lesson: treat AI feedback summaries as triage signals, then correlate with app version, crash data, logs, and reproduction.
- Card confidence: high for documented product capabilities; low for broad adoption/popularity and causal outcome claims.
